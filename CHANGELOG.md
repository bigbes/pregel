# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

The port of the 2016 Tarantool 1.6 library to Tarantool 3. The vertex-centric
model and the shape of the compute function are unchanged; everything that
touched Tarantool itself was rewritten, and two pieces were replaced rather
than ported — the vendored C Avro binding and the tarantoolctl deployment.

### Added

- `master.new` option `max_supersteps`: a positive integer, or nil for the unbounded runs that were the only kind. `master:start()` loops while a vertex is active or a message is in flight, so an algorithm that does not converge had nothing to stop it; with a limit set, the run that is still going after that many supersteps raises `pregel: superstep limit <n> reached with <k> active vertices and <m> messages in flight` -- the two counts are the internal aggregators, so the message says whether the job was spreading messages or sitting on vertices that refuse to halt. An unbounded run logs a warning naming the option every hundred supersteps (pregel-3wg).
- `pregel.roles.master` and `pregel.roles.worker`: Tarantool 3 roles that build a whole job out of `roles_cfg`, with `validate`/`apply`/`stop` plus a `get()` accessor and a `status()` for driving and watching one.
- `roles_cfg.autostart` on the master role: a background fiber waits for the workers, preloads the graph and runs the supersteps, reporting `idle`/`loading`/`running`/`done`/`failed` through `status()`.
- Participant discovery: a role whose `roles_cfg` names no `workers` (or no `master`) reads the cluster config and takes every instance running the other role for a job of the same `name`.
- `pregel.avro`: a self-contained pure-Lua Apache Avro implementation, replacing the vendored RedJack C binding.
- `pregel.avro.schema`: schema parsing from JSON text or a Lua table, validation, the Parsing Canonical Form, `tojson()`, and CRC-64-AVRO fingerprints.
- `pregel.avro.codec`: binary encoding and decoding of every Avro type, plus `skip` for walking past a value without building it.
- `pregel.avro.ocf`: object container file reader and writer with the `null`, `deflate` and `zstandard` codecs, and `read_all`/`write_all`/`schema_of` shorthands.
- `pregel.avro.deflate`: a pure-Lua RFC 1951 inflater, so a `deflate` container file is readable under Community Edition, where `compress.zlib` does not exist.
- `pregel.compress`: Tarantool Enterprise's `compress` module where there is one, and an FFI binding to the system libz, libzstd and liblz4 where there is not, with the same API and the same bytes. `implementation` names which side answers, `available(name)` says whether a codec works in this build, and `compress.ffi` reaches the FFI implementation under every build. Measured against the Enterprise 3.7 binary: its `compress.lz4` emits raw LZ4 blocks rather than the LZ4 frame format, and its `decompress_buffer_size` default of 1 MiB is a hard limit; both are matched here.
- `pregel.compress.zlib` honours `window_bits` in both directions — 15 for zlib framing, -15 for raw RFC 1951, 31 for gzip. Enterprise's honours it when compressing only, which is what left raw deflate write-only there.
- `pregel.compress.lib`: the run-time library lookup, preferring symbols the Tarantool binary already exports and otherwise trying sonames, the Homebrew and `/usr/local` prefixes, the Linux multiarch directories and `PREGEL_COMPRESS_LIBDIR`. The handle is cached and a failure names every path tried.
- `PREGEL_AVRO_PURE_LUA=1`, and `avro.deflate.force_pure`, select the pure-Lua inflater whatever else is available, so the fallback keeps being exercised on machines that have zlib.
- `avro.codec_available(name)` at the top level of `pregel.avro`, returning the implementation as a second value.
- `pregel.avro.resolve`: schema resolution between a writer and a reader schema, with resolvers cached per pair.
- `loader.avro_files`: a streaming loader over a pair of vertex/edge object container files, which splits itself by the pool's own hash so N workers reading the same two files cover the graph exactly once.
- `tools/text2avro.lua`: converts the two-section text graph format into that pair of files.
- `pregel.worker.grant` and `pregel.master.grant`: per-function `lua_call` grants for the four RPC entry points, and read/write on one instance's spaces and sequences.
- `worker.new` option `grant_to`: the users allowed to reach this instance, granted once its spaces exist.
- `pregel-scm-1.rockspec`, `.luacheckrc` and a `Makefile` with `deps`, `lint`, `test`, `test-under` and `test-ee` targets.
- A luatest suite: unit tests for every module, and multi-process integration tests over a real master and three workers — one harness starting bare instances and calling `new()` over net.box, one writing a cluster config and letting the roles applier do it.
- Reference Avro fixtures generated by fastavro 1.12.2, and cross-implementation tests that compare bytes in both directions.
- A README describing the current library: the roles and an annotated cluster config, the programmatic API, the loaders, the vertex API, aggregators, topology-mutation ordering and the Avro module.

### Changed

- Halting is what a superstep does by default: a compute function that returns without calling `vote_halt` leaves its vertex halted, where it used to leave it active. `run_superstep` un-halted every vertex it was about to compute, so a compute that never voted kept the whole graph active and the master looped until something killed it. A vertex that wants another superstep with no message to wake it says `vote_halt(false)`; a message still wakes a halted vertex, and every example already voted explicitly (pregel-3v3).
- RPC between instances is `conn:call()` against the `_G.pregel` registry rather than `conn:eval()`, so a peer needs `execute` on four `lua_call` names instead of `execute` on `universe`.
- Spaces and indexes are created for Tarantool 3: `space:auto_increment()` is gone, so the primary keys of the queue and topology-mutation spaces draw from a sequence.
- `worker.new`'s `squash_only` and `queue_engine` options are read from the options table, so they now do something.
- The message queue's two engines (`space` and `table`) are behind one interface, and `squash()` is actually called from the end of a superstep.
- Outgoing connections take `user`/`password` from the options table as well as from the URI, wait for a bounded time rather than forever, and are logged with any credentials stripped from the URI.
- A local bucket is detected from the connection greeting's peer uuid against `box.info.uuid` — `box.info.server.uuid` is gone — and then calls the registry function in process instead of looping back through net.box.
- The `deflate` and `zstandard` container-file codecs go through `pregel.compress`, so both compress for real on Community Edition rather than only under Enterprise: `deflate` writes real deflate instead of stored blocks, and `zstandard` exists at all. Two tests that used to skip themselves on Community Edition now run there, leaving the SSL transport test as the only skip.
- Reading a `deflate` block goes through zlib rather than the pure-Lua inflater wherever a libz can be loaded, Enterprise included — Enterprise's own module cannot decompress raw deflate. The Lua inflater stays as the fallback and stays the guarantee that a `deflate` file is readable anywhere.
- `avro.ocf.codec_available(name)` returns the implementation as a second value (`'ffi/ffi'`, `'enterprise/ffi'` or `'stored/pure-lua'` for `deflate`; `'enterprise'` or `'ffi'` for `zstandard`). Its first return value is still a plain boolean.
- luacheck covers the whole tree, `pregel/` and `tools/` included; the core carried an exemption while it was still 1.6 code.
- The Makefile gives luatest a `VARDIR` keyed by a checksum of the checkout path.

### Removed

- `CMakeLists.txt`, `cmake/` and the C build: the library is pure Lua and installs from the rockspec.
- `pregel/avro/` as it was — the vendored RedJack `lua-avro` binding (`legacy.c`, `c.lua`, `constants.lua`), unused by the core.
- The tarantoolctl `example/` directory: its scripts, its `.tarantoolctl` and its worker launcher. The graph data moved to `test/fixtures/graphs/`.
- `test-unit/`, which exercised an `aggregator` option and a `take` method that no longer exist.
- Unused helpers from `pregel.utils`, which is now `error`, `syserror`, `traceback`, `xpcall_tb`, `timeit` and `is_callable`.

### Fixed

- `mpool:wait_connected()` called a peer connected as soon as its iproto answered, so a worker that was up before its role had applied — the ordinary case during a cluster start, since nothing sequences the role appliers — answered the master's first call with "Procedure `pregel.worker.deliver` is not defined" and sent the job to `failed` for good, with no alert and nothing retrying. The pool now probes the entry point (a `ping` message on `pregel.worker.deliver`, so no new `lua_call` grant) and keeps such a peer in `connecting` until it serves or the role's `connect_timeout` runs out (pregel-ib4).
- A delayed `edge.delete` mutation removed only the first parallel edge to the destination, while the local `delete_edge` path removes every one (pregel-iv7).
- `pregel.utils.error()` formatted a lone message through `string.format`, so re-raising a caught error whose text contained a `%` reported the formatting failure instead of the message (pregel-2qk.1).
- `strict.strictify()` keyed its declared-key sets on the address in `tostring()`, which leaked and collided once an address was reused (pregel-2qk.1).
- The queue's `receiver_closure()` seeded a string index with the number 0 and returned out of its own loop, so it never walked past the first receiver; `pairs()` did not thread the iterator state back; and `squash()` deleted and re-put each receiver while iterating the container it was mutating (pregel-2qk.2).
- `queue:verify()` compared the stats value against the receiver name, called `index:len{k}` with an argument that method does not take, and printed through `print()` with format arguments it never applied, so it could not report a divergence. It returns `(ok, problems)` now (pregel-2qk.2).
- Reading the queue materialised the receiver through its defaultdict, and the worker asks about every vertex it walks — so every vertex became a live receiver (pregel-2qk.2).
- The message pool built a flush batch out of the accumulation slots the next `put()` reuses, so a producer running during the send rewrote the batch underneath it and the wrong messages arrived under the right count (pregel-2qk.3).
- A waitpool handler whose bucket raised died with the error and never answered on its output channel, so `send_wait()` waited forever (pregel-2qk.3). The input channel was given a capacity at the same time; the reason recorded for it then was wrong — a zero-capacity channel dispatches perfectly well to handlers that are all waiting in `get()`. What the capacity is actually for is that handing out the tasks must not block, or `send_wait()` never reaches the liveness check below (pregel-hr3).
- A delayed bucket deleted its messages before the send rather than after, so a failed send dropped them — and the space is their only copy (pregel-2qk.3).
- `vertex:compute()` called `table.insert` with one argument and looped over the deletion list without a step, so a vertex could neither add nor delete its own edges (pregel-2qk.4).
- `vertex:add_edge()` sent `{dest, value}` where the worker's handler expects `{src, dest, value}`, and `vertex:delete_vertex()` shifted its arguments so the vertex name landed in the destination field (pregel-2qk.4).
- `vertex:send_message()` omitted the sender, which `message.deliver` documents and a combiner has no other way to learn (pregel-2qk.4).
- Pooled vertex objects shared their pending edge additions and deletions, so mutations requested by one vertex were applied to the next (pregel-2qk.4).
- `vertex_delete_delayed()` inserted a stray field between the mutation type and the vertex name, so the name landed in the destination field and the index looked for a vertex called "2" (pregel-2qk.5).
- The delete-vertex pass was inverted: it logged "deleted" when the delete returned nil and then indexed that nil (pregel-2qk.5).
- The edge passes read the edge list of a vertex that is not on this worker without a guard, crashing the whole superstep, and selected the `(type, name)` key against the primary index (pregel-2qk.5).
- An aggregator declaring neither `merge` nor `reduce` was rejected by an assert that should have accepted it, because `merge` defaulted to nil rather than to `reduce` (pregel-2qk.5).
- The master's unknown-operation path called the global `error()` with format arguments, so it raised `bad argument #2 to 'error'` instead of naming the operation (pregel-2qk.5).
- `loader:store_edge()` built `{src {dest, value}}`, which Lua parses as a call of a string, and `store_vertex_edges()` passed the whole vertex where the source name was expected (pregel-2qk.6).
- The text loader dropped or duplicated the last line of a file without a trailing newline, and failed on blank lines (pregel-2qk.6).
- Two checkouts running the suite at once wiped each other's live servers, because luatest wipes its `VARDIR` at startup and the default is the host-wide `/tmp/t` (pregel-biq).
- `avro.encode('long', ...)` silently saturated or wrapped a value outside the int64 range, `validate` accepted such values, and a `{long, double}` union sent `1e300` down the long branch (pregel-co5).
- `schema:tojson()` rendered an empty map or record default as `[]` when the schema was given as a Lua table, which fastavro and Java reject in a container file header (pregel-eh0).
- `schema:tojson()` dropped the null namespace of a nested named type, so a container file's header named a different type than the data was encoded with (pregel-xm1).
- Schema resolution matched records, enums and fixed types on the fullname; the specification matches on the unqualified name (pregel-qfl).
- `mpool:flush()` skipped a bucket whose count was 0, which is what a bucket the background pusher has taken a batch from looks like — so every phase boundary that goes through it (`run_superstep`, `preload`, the master's `inform_workers`) returned while messages were still travelling. Under `wal_mode = 'write'`, or with a compute function that yields, a message was then read a superstep late or truncated away by the queue swap, `count` ran over a half-applied preload and `in_progress` went negative, and an `edge.store` could arrive before the `vertex.store` it depends on. A bucket now tracks its in-flight batch, only one send is in flight at a time so batches keep their order, and `flush()` drains every bucket (pregel-bk9).
- A background flush that raised killed the pusher fiber and took the batch with it, so a superstep reported `ok` over messages that never arrived and the next producer to fill that bucket waited forever on a flush nobody would perform. The failure is recorded on the bucket and raised from `put()` and `mpool:flush()` (pregel-qec).
- A worker kept the master's merged aggregator value in the very field the next superstep's contributions reduce into, and reported it back — so the master merged the global once per worker on top of the new contributions, and a summing aggregator accumulated over the whole run and across workers. `vertex:get_aggregation()` answered that live accumulator, so what a vertex read depended on how much of its own shard had been computed before it (pregel-3e8).
- `worker.grant()` did not cover the `delayed_push` bucket spaces, and compute runs inside the `pregel.worker.deliver` RPC with the caller's privileges — so `delayed_push = true` failed with "Write access to space 'pregel_mpool_…' is denied" under the module's own grants (pregel-bby).
- `queue.new()` answered from its cache whatever options it was asked for, and `worker:stop()` left its queues in that cache, so a worker recreated under the same name silently inherited the old combiner, `squash_only` and engine. Mismatched options are refused now, and `stop()` detaches the queues without dropping their spaces (pregel-crp).
- `send_wait()` waited on its output channel with no timeout, so a handler fiber that died holding a task hung the master — and hung the test suite instead of failing one test when the defect it covers was reintroduced (pregel-ub3).
- The message pool created its connections with `reconnect_after = 5` and then waited for them, so every cluster start paid five seconds whenever a peer was still bootstrapping: the first attempt fails with "Instance bootstrap hasn't finished yet" and net.box sat out the whole interval before retrying. Measured on the roles suite, 19 of 50 test cases took 5.63 s instead of 0.67 s. The interval is 0.1 s now, since it governs the first retry as much as the later ones (pregel-0jo).
- A role's `apply()` connected to every peer, inside the config framework's synchronous `post_apply` — so an instance that was down held up the others' startup for 30 s and then killed them, a post_apply error at startup being fatal, and nothing retried afterwards. Both roles now build the pool without connecting and wait in a fiber: `status()` reports `connecting`, each failed attempt is logged with the peer and net.box's reason, and giving up after `roles_cfg.connect_timeout` (default 300 s) publishes a `warn` alert instead of raising (pregel-8c2).
- "cannot connect within 30 seconds" was all a wrong password or an unknown user got, while net.box had been holding "User not found or supplied credentials are invalid" all along. `conn.error` is in the message now, and a rejected authentication ends the wait rather than being retried to the timeout — the connection state cannot tell it from a peer that is merely down, but the error can (pregel-roh).
- Discovery counted the read-only replicas of a worker replicaset as workers of the job, so every instance dialled an address that would never serve pregel and a replicated replicaset could not start at all. A replicaset is one participant now, addressed through the instance the config says will be read-write; where the config names no leader (`election` and `supervised` failover) the role asks for an explicit `workers` list. The replica itself no longer fails to apply — refusing there exits the process — but goes inert with `status()` `{state = 'read_only'}` (pregel-5tj).
- A discovered peer lost the transport parameters of its `iproto.listen` entry, so an Enterprise cluster listening with `transport: ssl` was dialled in plaintext: the listening side logged `SSL_write()` for every pregel connection and every instance died 30 s later. The peer is passed to net.box as the `{uri = ..., params = ...}` table it accepts (pregel-3lv).
- Taking the master role off an instance mid-job left `status()` reading `failed` / "fiber is cancelled" for good and logged a job failure that had not happened: `stop()` set the terminal state and *then* cancelled the autostart fiber, whose failure branch overwrote it. `stop()` now clears the job first, and the fiber ignores its own cancellation (pregel-dxl).
- `validate()` accepted an empty `name`, `app`, `master` or `user`, a `password` with no `user` to use it, and an aggregator option the app module misspelt. An empty `app` reached `package.searchpath` and came back with "bad argument #1 to searchpath", naming neither the role nor the option (pregel-ilf).
- The roles raised with a source position, so a config alert read `/Users/.../pregel/roles/common.lua:96: pregel.roles.worker: option name must be string, got number`. They raise with level 0 now, as Tarantool's own roles applier does (pregel-lo1).
- Three fixes had no test that went red when they were undone: discovery dropping the replication login from a peer URI (held by mpool's `user` option in every existing test, not by discovery), the master's `stop()` cancelling the autostart fiber, and `check_writable` — no test put a role on a read-only instance or removed the master role at all (pregel-9vt).
- A compute function that raised wedged the worker for the life of the process instead of failing the job. The exception skipped the return of the pooled vertex object, and `run_superstep` ends with `while vertex_pool.count > 0 do fiber.yield() end` — a loop nothing else can satisfy — so every later superstep spun. Nothing upstream converted that into a failure either: a bucket calls with no timeout and the waitpool only notices a handler that has *died*, so `master:start()` stopped at `send_wait('superstep')` and stayed there. The compute now runs under `xpcall`; the vertex object goes back first, the superstep stops at the failing vertex rather than computing the rest of the shard against a half-applied state, and the RPC raises a `PregelComputeFailed` `box.error` reading `pregel: compute failed on vertex '<id>' in superstep <n>: <message>` and carrying `pregel_code`, `vertex`, `superstep`, `pregel_message` and `traceback` as payload. The entry points and mpool's waitpool re-raise the error object rather than its text, so the payload reaches `master:start()` intact (pregel-2c0).
